# Corrección de navegación y HTTP 429 — Instagram

## Problema
El discovery abría directamente el perfil del prospecto y después volvía a abrir directamente la publicación con `driver.get()`. En una ejecución con varios hashtags/candidatos esto podía producir una ráfaga de navegaciones y dejar la sesión en una página de rate limit 429.

## Cambios
- `InstagramProfileService` ahora detecta páginas de rate limit sin depender de que Selenium exponga el status HTTP.
- Al detectar 429 se activa un cooldown y no se realizan nuevas navegaciones directas durante ese periodo.
- `ensure_follow_profile()` devuelve `rate_limited` para que el discovery pueda detenerse limpiamente.
- El discovery detiene el resto de hashtags/candidatos cuando aparece un 429; no martilla Instagram con reintentos.
- Después de visitar el perfil para hacer follow, se usa `driver.back()` para volver al post original en lugar de hacer otro `driver.get(post_url)` cuando es posible.
- El retorno al post en la recolección de posts recientes no se intenta si ya existe un rate limit.
- Se añade una separación mínima configurable entre navegaciones directas.

## Variables
En `.env.example`:
- `INSTAGRAM_PROFILE_NAV_GAP_SECONDS=2.5`
- `INSTAGRAM_429_COOLDOWN_SECONDS=90`

Se pueden ajustar en el `.env` real. No es necesario añadirlas para que funcione: existen valores por defecto.

## Validación
- Todos los `.py` del proyecto (excluyendo `.venv`) compilan correctamente con `py_compile`.
- La suite completa no pudo ejecutarse en este entorno porque el Python disponible no tiene Selenium instalado; el proyecto incluye su `.venv` de Windows, que no es ejecutable en este entorno Linux.
- La validación real de Instagram debe hacerse en el Windows del bot con la sesión real.

## Comportamiento esperado
Ante un 429 debe aparecer en el log algo similar a:

`[instagram-rate-limit] 429 detectado; pausando navegación durante 90s`

seguido de:

`[instagram-rate-limit] discovery detenido; no se procesarán más hashtags en esta ejecución.`

No se debe hacer un nuevo `driver.get()` inmediatamente después del 429.
